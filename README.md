# 校集：通达校园 Agent 平台

当前版本说明，核对日期：2026-10-27。面向南京邮电大学通达学院，生活查询默认学校周边3公里，最多5公里。

## 启动

双击本目录「打开原型.command」（Windows 副本为「打开原型.cmd」）。如果服务已运行，会直接打开页面；否则启动本机后台，使用期间保持启动窗口打开。也可以在本目录运行 `node server.cjs`。

在浏览器访问 http://127.0.0.1:4173 。不要直接打开dist/index.html，本版本需要后台。当前服务仅监听本机地址，尚未部署为全校可访问的网站。

## 直接问生活助手

进入「校园生活助手」，可以问：

- 通达附近有什么吃的？
- 学校旁边哪里喝咖啡？
- 学校周边5公里哪里看展？
- 学校附近哪里打印？
- 学校附近哪里有快递点？
- 通达两公里内哪里洗衣？
- 通达外卖能送到宿舍楼下吗？

明确的周边地点问题会自动查询本机公开地点库，不必先操作地图表单。也可以使用「通达周边吃喝玩乐」表单查询，再勾选参考本次结果。默认查询中心是学校公开地图代表坐标，不获取用户个人定位。

已配置豆包时，勾选云端发送确认后提问；发送内容包括当前问题、相关资料和匹配的地点片段。地点搜索本身不调用地图接口，豆包回答仍计入模型调用。没有配置豆包也可以使用地点搜索与本地资料检索。

结果中的距离为直线距离，不是校门出发的步行距离。校园区域提示依据社区地图推测，不表示已确认允许进入、可以代收快递或正在营业。未收录不等于附近没有。价格、优惠和实时营业状态尚未接入。

## 互助通达

同学之间可以互相登记「我能帮忙」或「我需要帮忙」：类型自己写，登记时选择生效时段或长期，过期或下架后自动退出匹配。提问按语义匹配当前生效的登记，找到后再选择是否开聊；同意之前不会建立对话。发布和开聊需要学号登录（本机演示账号，不是学校真实认证），联系方式由发布者自愿公开。发布者会在页面的「别人发来的消息」里看到私聊和未读数并直接回复，停留在这个页面时会定时刷新；私聊页不显示双方学号。登记可以被其他同学举报，管理员在「审核管理」的「互助举报」里选择下架或忽略。发布、提问、私信和登录都有本机内存限流（重启服务后清零）。目前只有少量测试数据，尚未面向同学开放。

互助登记与私聊不做发布前人工审核；提交时会自动做内容安全检查，命中违规内容即拒绝且不保存。旧的「发布前审核」代码仍保留为实验开关（`BOARD_REVIEW=1`，默认关闭，界面不提示）。

## 内容安全检查

互助登记和私聊消息提交前会做两层检查：先查本地违规词表（色情、赌博、毒品枪支、诈骗/刷单、代考代写、证件买卖、身份证/银行卡/验证码等），配置了云端模型时再让模型做一次语义判断；命中后直接返回 400，内容不会写入数据。模型超时、报错或返回格式不对时只走本地词表（fail-open），不会因为模型故障误伤正常登记。

- 追加本地词表：启动时设置 `BOARD_BLOCK_KEYWORDS="词1,词2"`（中英文逗号均可）。
- 关闭检查：`BOARD_MODERATION=0`。
- 模型检查会调用当前配置的云端模型，因此登记/私聊文本会发送到该服务；不想发送就关闭 `BOARD_MODERATION`，只用本地词表需要另行调整代码。

## 提交资料

进入「资料贡献」，填写标题、目标助手、来源及正文摘要。原文链接、发布日期、采集日期分别填写；不知道原发布日期就留空，不要用今天代替。选择「官方通知」「个人体验」「商家宣传」或「未确认」。

抖音、小红书资料需保留原帖链接与时间，并在内容中说明具体门店、与通达周边的关系以及哪些事实尚未核实。粘贴链接只会保存来源，不会自动抓取网页。TXT/MD可以读取文字；PDF/DOCX目前需要手工填写摘要，原文件不会存入知识库。

提交的内容默认待审核，不参与回答。只有通过审核的资料可以进入知识问答；社区地图点位另标来源，不能冒充学校审核资料。

## 审核与团队

右上角可切换演示身份。管理员在「审核管理」查看正文、来源链接、日期和内容性质，确认后通过或填写原因驳回。被驳回的资料由提交者修改重提，仍需重新审核。下架资料保留在后台，但退出检索。

演示身份里的团队成员只有一个入口。在「团队工作台」统一维护生活、办事和学习助手，填写职责与回答规则，提交后由管理员审核上线。平台管理员可以直接进入「团队工作台」维护和提交助手（演示身份，不是真实权限），上线仍需在「审核管理」通过。

当前身份切换用于本机演示，不是真实账号登录或适合开放互联网的权限体系。现有版本适合在自己电脑上测试项目流程。

## 当前数据与保留方式

已审核资料共218条：生活43、学习78、办事97，另有下架59条、驳回2条。学校周边公开地点59个（2026-09-23 采集的快照）；其中部分位于邻校内部，查询时显示已核对的地图区域线索。

公开来源与导入记录在imports目录。旧的全扬州地点快照保留为归档，当前生活助手使用通达周边数据；较远生活资料已下架。

知识库保存在data/store.json，地图资料保存在lib/places-osm.json，校园区域资料在lib/campus-areas.json。模型密钥由本机 config.local.json 保存，这是本地机密，不要公开分享，也不要提交到仓库。同步或更新只覆盖程序文件（dist/、lib/、tests/ 等），不要覆盖、删除或改写 config.local.json；启动脚本也不会动它。服务重启后，已经保存的密钥仍然有效，不必重新填写。备份知识资料时可先停止服务，再复制 data、lib 与 imports 目录，密钥文件单独保管。

不要随意点击「重置演示数据」：它会恢复初始演示资料，并清除后续导入内容，不是刷新页面。

## 部署

本机演示版只监听 127.0.0.1，不要直接暴露到公网。需要给校内使用时，按 [deploy/README.md](deploy/README.md) 配置 TLS 反向代理：代理保留浏览器原始 Host、转发 `X-Forwarded-Proto`，应用启动时设置 `CAMPUS_ORIGINS=https://你的域名`（应用据此校验 Host/Origin，并给会话 Cookie 加 `Secure`）。`deploy/` 里还有 systemd / launchd 启动文件与备份脚本。

注意：当前 `/api/session` 仍可一键切换管理员演示身份，未接真实登录前只建议放在内网，或在最外层再加 SSO/VPN。限流是进程内内存计数；经反向代理后客户端 IP 统一显示为本机，限流会退化为全局限制，重启服务后清零。
